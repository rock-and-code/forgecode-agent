# MVP Slice 1 implementation plan: deterministic controller loop

Date: 2026-08-08  
Status: RED tests created; no production implementation yet.

## Goal

Implement the smallest ForgeCode Agent core that satisfies the first unit test suite while preserving strict TDD and safety-first defaults.

## Required public API

Create `src/forgecode_agent/` with focused modules only after reviewing the RED tests:

- `forgecode_agent.models`
  - `ToolIntent(name: str, arguments: dict)` value object.
  - `AssistantMessage(content: str = "", tool_intents: list[ToolIntent] = [])` value object.
  - `FakeModelProvider(script: list[AssistantMessage])` with deterministic `complete(messages=...)` and recorded `requests`.
- `forgecode_agent.policy`
  - `ApprovalMode` with at least `READONLY` and `SUPERVISED`.
  - `ApprovalPolicy(mode, approved_actions)` with `decide(tool_name, risk, arguments)` returning a decision object.
  - Read-only tools auto-allow; write/shell/git actions require approval in supervised mode; readonly mode blocks mutation even if preapproved.
- `forgecode_agent.tools`
  - `ToolDefinition(name, risk, description, parameters, handler)`.
  - `ToolRegistry` with `register`, `execute`, `calls`, and `clone_empty_history`.
  - `ToolCallDenied` for unknown tools or policy denial.
- `forgecode_agent.ledger`
  - `RunLedger(run_id)` that appends ordered events.
  - Event objects expose `type`, `data`, and `to_dict(exclude={...})` for deterministic comparisons.
- `forgecode_agent.agent`
  - `AgentController(model_provider, tools, approval_policy, ledger, max_iterations)`.
  - `run(goal)` starts a run, asks the model, executes one read-only tool intent, sends the tool result back to the model, records events, and returns a result with `final_answer`, `completed`, and `iterations`.
- `forgecode_agent.cli`
  - `DoctorStatus` value object.
  - `doctor_status(workspace)` pure/testable function.
  - `main` entrypoint wired later for console script compatibility.

## Implementation order

1. Add package skeleton and dataclasses with no extra behavior.
2. Make `FakeModelProvider` tests pass.
3. Implement `ApprovalPolicy` and reason codes exactly as tests specify.
4. Implement `ToolRegistry` lookup, policy enforcement, call history, and denial errors.
5. Implement `RunLedger` event append/to-dict behavior with stable ordering.
6. Implement only the one-iteration controller path required by tests.
7. Implement `doctor_status` as a pure function; avoid subprocess use.
8. Run `pytest` after each step and stop when this first slice is green.

## Constraints

- Keep production code minimal; do not add real model providers, shell execution, git mutation, or file writes in this slice.
- No network calls.
- No subprocess calls for `doctor_status`.
- Preserve deterministic behavior: stable event order, stable request recording, no random IDs in tests.
- Treat tool outputs as data; do not convert them into instructions.

## Next tests after green

- Max-turn/budget exhaustion.
- Malformed tool arguments.
- Multiple tool calls and policy-denial stop behavior.
- Ledger JSONL persistence/redaction.
- CLI `main` argument parsing for `forgecode doctor`.
